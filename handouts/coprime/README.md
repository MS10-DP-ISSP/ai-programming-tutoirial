# 互いに素な確率による円周率の近似

1 以上 N 以下の整数 a, b をランダムに選んだとき、a と b が互いに素になる確率は N → ∞ で 6/π² に近づきます。
このディレクトリには、N × N 通りの組 (a, b) をすべて数え上げて互いに素な割合 `prob` を求め、`sqrt(6 / prob)` で π を近似するプログラムを複数の言語で用意しています。
どの言語も N = 10000 で計算します。

## ディレクトリ構成

| ディレクトリ | 言語 | 内容 |
| --- | --- | --- |
| [`c/`](c/) | C | ユークリッドの互除法による素朴な実装 |
| [`js/`](js/) | JavaScript | C 版と同じアルゴリズム |
| [`jl/`](jl/) | Julia | 素朴な実装 (`naive.jl`)、標準の `gcd` を使う版 (`stein.jl`)、Stein のアルゴリズムを書き換えた版 (`opt.jl`) |
| [`rs/`](rs/) | Rust | Julia 標準の `gcd` (Stein のアルゴリズム) を Rust に移植したもの |

`julia/` は Julia 本体のソースを参照用に置くためのディレクトリで、Git の管理対象外です。

## 実行方法

```sh
# C
cd c && bash run.sh

# JavaScript
cd js && node main.js

# Julia
cd jl && julia naive.jl
cd jl && julia stein.jl
cd jl && julia opt.jl

cd rs && cargo run --release
cd rs && cargo test
```

C、Julia、Rust 版は `calcPi` の実行時間も表示するので、言語や GCD の実装による速度の違いを比べられます。

## Stein のアルゴリズム (binary GCD)

ユークリッドの互除法は剰余 `a % b` を繰り返し計算しますが、整数の除算は CPU にとって重い命令です。
Stein のアルゴリズムは除算を使わず、2 で割る操作 (右シフト) と引き算だけで GCD を求めます。
使う性質は次の 3 つです。

- a, b がともに偶数なら `gcd(a, b) = 2 * gcd(a/2, b/2)`
- 片方だけが偶数なら、その数を 2 で割っても GCD は変わらない
- a, b がともに奇数なら `gcd(a, b) = gcd(|a - b|, min(a, b))`。このとき `|a - b|` は偶数になる

計算の手順は次のとおりです。

1. a と b の二進表現の末尾の 0 の数 (`trailing_zeros`) を数え、小さいほうを k とする。2^k が共通の 2 の因子になる
2. a と b をそれぞれ末尾の 0 の数だけ右シフトして、両方を奇数にする
3. 2 数が等しくなるまで、`|a - b|` から 2 の因子を取り除いたものと `min(a, b)` で置き換える
4. 残った値を k ビット左シフトして 2^k を掛け戻す

例えば `gcd(48, 18)` では次のように進みます。

| 手順 | a | b | 説明 |
| --- | --- | --- | --- |
| 1 | 48 = 110000₂ | 18 = 10010₂ | 末尾の 0 は 4 個と 1 個なので k = 1 |
| 2 | 3 | 9 | 2 の因子を取り除く |
| 3 | 3 | 3 | \|3 - 9\| = 6 から 2 の因子を除いて 3、min は 3 |
| 4 | | | 3 << 1 = 6 |

`trailing_zeros` は多くの CPU で 1 命令 (x86 の `tzcnt` など) で計算できるので、ループ 1 回あたりの処理はシフト・減算・比較だけで済みます。
`jl/stein.jl` は Julia 標準の `gcd` を使い、`jl/opt.jl` と `rs/` はこの手順を自前で実装しています。
